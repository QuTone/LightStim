# Planar subsystem surface code

`SubsystemSurfaceCode(distance=d)` implements the hole-free planar triangle
code with parameters `[[3*d*d-2*d, 1, (d-1)**2, d]]`, for integer `d >= 2`.
Data and ancilla coordinates follow a rotated patch of distance `2*d-1`, with
the periodic data sites `(4*i+3, 4*j+3)` omitted. Bulk weight-three gauges have
ancillas at their hypotenuse midpoints; weight-two boundary checks retain
the rotated patch's ancilla positions. X/Z labels follow LightStim's convention.

The declared center contains `2*(d-1)**2` weight-six checks and `4*(d-1)`
weight-two boundary checks, all independent. There are `4*d*(d-1)` measurement
ancillas. The center is declared separately from the measured gauge generators;
it does not change between measurement phases. Bare logical representatives
have weight `2*d-1`, while the minimum dressed logical weight is `d`.

`SubsystemSurfaceCodeExtractionBlock` is the default for `MemoryExperiment`.
It measures X gauges and boundary checks, then Z gauges and boundary checks,
with reset, four local CNOT slots, and readout in each phase. Bulk ancillas use
three of the four slots. This eight-CNOT-layer baseline is not the original
paper's four-step interleaved schedule, which uses additional ancillas to hide
preparation latency. Noise and detectors are generated by the existing
LightStim memory pipeline, not inserted by the extraction block.

```python
from lightstim.protocols.memory import MemoryExperiment
from lightstim.qec_code.subsystem_surface import SubsystemSurfaceCode

circuit = MemoryExperiment(
    qec_patch=SubsystemSurfaceCode(distance=3),
    basis="Z",
    rounds=2,  # each round is a complete X/Z cycle
).build()
```

The [memory notebook](../../../notebooks/Memory/memory_subsystem_surface.ipynb)
shows the circuit and a small CPU-MWPM decoding example. The existing memory
benchmark accepts `--codes subsystem_surface`; it retains all automatic
detectors and defaults to `rounds=distance` complete X/Z cycles.

References:

- [Bravyi et al., arXiv:1207.1443, Section IV / Figure 4](https://arxiv.org/pdf/1207.1443#page=5).
- [Higgott and Breuckmann, arXiv:2010.09626, Section III](https://arxiv.org/pdf/2010.09626#page=3), which explicitly gives the planar `[[3*d*d-2*d, 1, d]]` parameters.

The distance argument follows the later paper's planar convention. The original
paper counts `L=d-1` plaquettes per side; the rotated geometric template has
distance `2*d-1`.
